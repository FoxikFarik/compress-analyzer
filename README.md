# Compress Analyzer

Программа для оценки качества автоматически сокращённых текстовых документов (конспектов).

Проект позволяет оценить, насколько хорошо конспект сохраняет информацию исходного документа, насколько сильно он сокращён и содержит ли повторяющиеся предложения.

## Возможности

Программа рассчитывает следующие метрики:

- **Compression Ratio** — отношение количества слов в конспекте к количеству слов в исходном документе.
- **Duplicate Rate** — доля повторяющихся предложений в конспекте.
- **Faithfulness** — степень соответствия утверждений конспекта исходному документу.
- **Precision** — доля утверждений конспекта, сопоставленных с эталонными.
- **Recall** — доля эталонных утверждений, сохранённых в конспекте.
- **F1** — гармоническое среднее Precision и Recall.

Precision, Recall и F1 рассчитываются только при наличии файла с эталонными утверждениями.

## Используемые методы

- **TF-IDF** — представление текстовых фрагментов в виде векторов для поиска и сравнения.
- **Косинусное сходство** — оценка сходства текстовых векторов.
- **Hungarian Algorithm** — оптимальное взаимно-однозначное сопоставление утверждений.
- **Natural Language Inference (NLI)** — определение логической связи между исходным фрагментом и проверяемым утверждением с помощью предобученной модели `MoritzLaurer/mDeBERTa-v3-base-mnli-xnli`.

## Входные данные

Для работы программы необходимы два документа:

1. **Исходный документ** — материал, на основе которого был составлен конспект.
2. **Конспект** — сокращённая версия исходного документа.

Поддерживаются форматы TXT и DOCX. Документы могут находиться в любой директории: их расположение указывается при запуске программы.

Дополнительно можно передать файл `claims.json` для расчёта Precision, Recall и F1.

### Файл claims.json

`claims.json` содержит наборы утверждений, используемых для сравнения конспекта с эталонным содержанием исходного документа.

Файл состоит из двух обязательных списков:

- `summary_claims` — утверждения, содержащиеся в конспекте.
- `reference_claims` — важные утверждения исходного документа, которые должны быть сохранены в конспекте.

Пример структуры:

```json
{
    "summary_claims": [
        {
            "text": "Вода замерзает при нуле градусов.",
            "sentence_index": 0,
            "paragraph_index": 0
        }
    ],
    "reference_claims": [
        {
            "text": "Вода замерзает при температуре 0 °C.",
            "sentence_index": 0,
            "paragraph_index": 0
        },
        {
            "text": "Вода кипит при температуре 100 °C.",
            "sentence_index": 1,
            "paragraph_index": 0
        }
    ]
}
```

#### Описание полей

Каждое утверждение представлено объектом со следующими полями:

| Поле | Описание |
|---|---|
| `text` | Текст утверждения |
| `sentence_index` | Индекс предложения, из которого взято утверждение |
| `paragraph_index` | Индекс абзаца, в котором находится предложение |

Индексация предложений и абзацев начинается с нуля.

Например, `sentence_index: 0` и `paragraph_index: 0` обозначают первое предложение первого абзаца документа.

Индексы относятся к соответствующему документу: для `summary_claims` — к конспекту, для `reference_claims` — к исходному документу.

#### Правила формирования утверждений

Разметка формируется вручную на основе исходного документа и конспекта.

При составлении разметки рекомендуется соблюдать следующие правила:

- Одно утверждение должно описывать один отдельный факт.
- В `summary_claims` включаются факты, действительно присутствующие в конспекте.
- В `reference_claims` включаются основные факты исходного документа, которые важны для сохранения смысла материала.
- Формулировки утверждений могут отличаться от исходных предложений, если сохраняют их смысл.
- Не следует добавлять в эталон факты, которых нет в исходном документе.

Количество утверждений в двух списках может различаться.

#### Использование при расчёте метрик

После загрузки `claims.json` программа выполняет сопоставление утверждений конспекта с эталонными утверждениями.

Для этого используется TF-IDF и косинусное сходство. Затем алгоритм Венгерского метода (Hungarian Algorithm) определяет оптимальные пары соответствующих утверждений. Для сопоставления используется порог сходства, по умолчанию равный 0.5.

На основании результатов сопоставления рассчитываются:

- **True Positive (TP)** — количество сопоставленных утверждений.
- **False Positive (FP)** — количество утверждений конспекта, которым не найдено соответствие в эталоне.
- **False Negative (FN)** — количество эталонных утверждений, которым не найдено соответствие в конспекте.

Далее вычисляются:

$$Precision = \frac{TP}{TP + FP}$$

$$Recall = \frac{TP}{TP + FN}$$

$$F1 = 2 \cdot \frac{Precision \cdot Recall}{Precision + Recall}$$

Если соответствующие знаменатели равны нулю, программа возвращает 0.

**Важно:** качество Precision, Recall и F1 зависит от полноты и корректности ручной разметки. Эти метрики оценивают сохранение заранее выделенных важных утверждений, а не автоматически определяют полноту всего исходного документа.

Файл `claims.json` является необязательным. Если он не передан при запуске, программа пропускает расчёт Precision, Recall и F1, но продолжает вычислять остальные метрики.

## Установка

Для работы требуется Python 3.10 или новее.

Установите зависимости:

```bash
pip install -r requirements.txt
```

## Запуск

Для оценки документов без эталонных утверждений:

```bash
python main.py source.docx summary.docx
```

Для полной оценки с использованием эталонных утверждений:

```bash
python main.py source.docx summary.docx claims.json
```

Можно указывать как относительные, так и абсолютные пути к файлам.

При первом использовании NLI-модели Hugging Face загрузит её файлы. В дальнейшем модель будет использоваться из локального кэша.

## Тестирование

Для запуска автоматических тестов:

```bash
pytest
```

## Ограничения

- Эталонные утверждения формируются вручную.
- Поиск релевантных фрагментов основан на TF-IDF и может не находить смысловые совпадения при существенном перефразировании.
- Faithfulness зависит от качества поиска фрагментов и предсказаний NLI-модели.
- Полученные оценки являются приближёнными и не гарантируют абсолютную точность оценки качества конспекта.
